### 7.1 P1 · 契约对齐（目标版本 v2.14.0）

**目标**：把「人-业务语义」固化为「机-可校验契约」，让八位家人的身份、能力、协议与指标只有**一处定义**。

| 编号 | 任务 | 交付物 | 验收标准 |
| ---- | ---- | ------ | -------- |
| **P1-T1** | 单一事实源 | `presets/family-manifest.yaml`：8 家人 × 能力 × 意图 × 五支柱 × 提示词版本，含 1207 的 8×8 A2A 通信矩阵 | `scripts/check-manifest.mjs` 校验与各 `agent.yaml` **0 漂移**；CI 软校验（warning，不阻断） |
| **P1-T2** | Agent Card | `scripts/gen-agent-cards.mjs` → `assets/agent-cards/*.json`（对齐 1207 schema：`name/description/url/version/provider/capabilities/skills/defaultInputModes/defaultOutputModes/authentication/security/slo`） | 8 张卡 + JSON Schema 校验用例入回归；字段缺一即失败 |
| **P1-T3** | MCP 适配器实装 | 将 [event-bus.ts](file:///Users/yanyu/YANYUCLOUDCUBE/YanYuCloudCube/YYC3-AI-FAmily-Agent/architecture-kernel/02-云枢核心引擎/family-communication-bus/event-bus.ts) 中 `registerMcpAdapter` 的 `TODO(infra)` 落实为 **codec + 本地 stdio transport**（现有 `McpAdapter` 只有 `id/encode/decode`，缺传输与失败路径） | 新增 ≥3 用例：encode / decode 往返、解析失败入 DLQ；门禁 97 → ≥100 |
| **P1-T4** | 五维指标映射 | `family_*` 14 项 → 五维（时间/空间/属性/事件/关联）；**仅新增 4 个协同度指标**（澄清率 / 人工确认率 / trace 覆盖率 / 复盘覆盖率） | 指标总数 ≤18；面板可读；`prometheus-rules.yaml` 增 4 条告警 |
| **P1-T5** | 提示词契约 | 1206 CO-STAR 规范 → `prompts/*.prompt.ts` 统一元数据（`id / version / vars / outputSchema`） | schema 校验通过；版本号回写 manifest，可 A/B |

**明确不做**：不引第三方依赖；不改 05↛07 依赖方向；**不把 129 个 Python 路由翻译成 TS**（翻译即负债）。

**进度（2026-10-23）**：P1-T1 ✅（清单 + 校验，漂移 0）｜P1-T2 ✅（8 张卡 + `--check` 零漂移）｜P1-T3 ✅（MCP codec + stdio + DLQ，9 例）｜P1-T4 ✅（五维映射 + 协同 4 指标 + 4 告警 + 面板五维卡片，6 例）｜P1-T5 ✅（16 提示词 CO-STAR 七要素 + `PROMPT_META` 元数据 + 版本回写清单 `prompts` 段 + `prompts:check` + 契约套件 8 例）｜**P1-T4b ✅**（四类零侵入仪表生产端接线：千行澄清 / escalation / 审计链 / 学习回流 + `recordReplay` 两端记账 + 装配层 metrics 注入即自动接线，8 例）｜门禁 **135 → 143/143**，门禁入口 13 → 19｜清单 v1.1.0、包版本 2.15.0｜**M6 + M7 达成，P1 五任务 + T4b 全部完成**；后续可选 P2 生态外挂（M8/M9）。

**节点**：M6 = P1-T1/T2 完成（契约可校验）｜M7 = P1-T3/T4/T5 完成（协议与指标闭环）。

### 7.2 P2 · 生态外挂（目标版本 v3.0，可选）

**目标**：让蓝图 `13` 的 Python 能力以「外部家人」身份参与协同，**不出现在 tsconfig、不进入 hermetic 门禁、不污染主仓依赖**。

| 编号 | 任务 | 交付物 | 验收标准 |
| ---- | ---- | ------ | -------- |
| **P2-T1** | 外部 worker 契约 | `presets/external-worker/worker.yaml.tpl`（`endpoint / capabilities / auth / timeout / fallback / capabilitiesRef`） | 与 `family-manifest.yaml` 的 capability id 对得上；不得自定义能力名 |
| **P2-T2** | A2A 适配层 | `architecture-kernel/a2a-adapter/`：**只做** card 发现（`/.well-known/agent-card.json`）+ 任务委托（JSON-RPC）+ 结果归一；复用 EventBus 与 DLQ | ≥3 用例（发现成功/超时/非法响应入 DLQ）；**纯内存 stub，零网络** |
| **P2-T3** | 外部门控 runner | `scripts/run-external-uats.mjs`：三闸（`EXT_WORKER=1` + 确认语 + 端点存在），缺一整体跳过并 exit 0 | 与 `uat:llm` 同构；默认**不进** `run-regression.mjs` SPECS；门禁口径仍为「跳过 0」 |
| **P2-T4** | 安全策略映射 | 1209 零信任 / 内容过滤 / 注入检测 → `PolicyRegistry.register()` 的 YAML 策略（`resources: model.input / tool.call`） | 默认 **observe** 模式只记审计；`enforce` 需显式开关 |
| **P2-T5** | 编排边界 | `docker/` 下独立 compose 模板（外部 worker 段，端口避开 3030 主服务） | 不参与 `pnpm regression`；不写进根 `package.json` scripts 必选链路 |

**明确不做**：不合并 Python 代码进编译范围；不把外部服务纳入 97 例门禁；不引入 Flask/pydantic 依赖；不在主仓启动常驻进程。

**节点**：M8 = P2-T1/T3（契约与门控）｜M9 = P2-T2/T4/T5（适配与策略）。

**风险与对冲**

| 风险 | 对冲 |
| ---- | ---- |
| 双运行时运维成本 | 仅本地/预发；默认不启动；无 compose 即无依赖 |
| 外部能力漂移 | capability 必须引用 manifest id，生成期校验 |
| 安全策略误拦截 | 默认 observe，enforce 显式开关 + 审计链留痕 |
| 有人把外部 UAT 插回回归 SPECS | 与 v2.13.0 同样在 SPECS 处留治理注释防回退 |
